# The feed layer: how any second brain gets fed

## The problem

Every second-brain approach argues about the brain: a wiki the model maintains (Karpathy), a database every agent can reach (Open Brain), a memory engine that consolidates and reflects (Hindsight), a personal AI system with its own memory tiers (Daniel Miessler's PAI). They all assume something has already put the right material in front of them.

That something is usually a person copying links by hand, or an ad-hoc script per source. The brain is only as good as what feeds it, and the feeding is the part nobody designs.

**The brain is a sink. The feed is the layer underneath every brain.**

## The pipeline

```
SOURCES ──► GUARD ──► JOURNAL ──► GRADE ──► ROUTE ──► SINKS
 rss/atom    secrets   append-only  against    pure       views:      wiki, page
 youtube     private   ledger       YOUR       rules,     (rebuilt from the ledger)
 github      spans     (dedup,      intent,    fan-out    deliveries: Hindsight, webhook,
 arxiv                 write-ahead)  optional              stdout, a review queue
 inbox, pipe                         model
```

1. **Sources** pull. One feed adapter covers blogs, Substack, YouTube channels, GitHub releases and commits, arXiv queries and most podcasts; a YouTube source adds each new video's captions. A folder inbox and a stdin pipe cover everything else.
2. **Guard** runs before anything is written: secret shapes become `[REDACTED:<label>]`, `<private>` spans vanish, every field is checked. The ledger can be shown on a projector.
3. **Journal** writes every item to an append-only ledger before any judgement. Nothing that was caught is lost when a grader or a sink fails. Identity is the normalized URL, so the same article from three inputs is one row; an item that comes back materially longer is a revision and is graded again.
4. **Grade** asks "good for what *I* am doing?", not "good?". The yardstick is a plain Markdown intent profile: interests with weights, projects with terms, things to avoid. The deterministic grader runs on every item and explains every point. A model grader is optional, plugs into any OpenAI-compatible endpoint, runs within a per-run budget, and adds summaries, quality, tier, importance, novelty, urgency and labels from a fixed set (the Summarize and Rate stages of Daniel Miessler's feed design).
5. **Route** is pure logic, no model: rules with AND conditions on score, labels, projects, source, kind and the model dimensions. Every matching rule fires; each sink receives an item once.
6. **Sinks** come in two kinds, because they obey different laws:
   - a **view** (wiki, page) is a compiled projection, rebuilt whole from the ledger, never edited and never the store;
   - a **delivery** (a memory engine, a webhook) hands the item over once and keeps a receipt. A **review queue** can sit in front of any delivery, so nothing reaches a memory until a person approves it.

## Why it is shaped like this: truth-change laws

A memory system has layers whose truth changes differently. Putting each layer under the right law is what keeps the system honest.

| Layer | How its truth changes | Here |
|---|---|---|
| What was captured | never: it happened | `ledger.jsonl`, append-only |
| What it means for me | when my intent changes | `grades.jsonl`, versioned by profile hash; `regrade` re-scores with no network |
| What I read | whenever I like | views, regenerated by `rebuild` |
| What the brain knows | the brain's own business | deliveries, with receipts; approvals in `review.jsonl` |

The wiki is a view, never the store (the Open Brain inversion). The memory engine owns consolidation and recall (Hindsight's retain / recall / reflect). The feed owns intake.

## Sources earn their place

Every source carries a rolling seven-day reputation from its model grades. A source with 30 or more rated items, a mean quality under 35 and nothing at 70 or above is demoted and skipped until `source reset`. A source that fails five times in a row is tried only every six hours until it works again. Both thresholds are configurable, and both show in `status` and `explain`.

## Your own voice is not content

Recordings of your own conversations and notes you mark as yours are your thinking, so they are never rated for quality. A separate stage reads them for what you decided, proposed, asked for and left open. Every candidate carries your exact words, checked against the transcript as whole words inside one turn, with the speaker shown as verified or not. Candidates wait in the review queue; nothing lands until you approve it, and it lands as an idea unless you type it as a decision. Text that tries to instruct the model is reported, never followed.

Two questions are asked of every item and never stand in for each other: **privacy class** decides where an item may go (a sink or a model port must say it accepts personal items), and **voice ownership** decides how it is graded.

## How it plugs into each approach

| Approach | What the feed gives it |
|---|---|
| **Karpathy's LLM wiki** | the `wiki` view: one note per source with frontmatter, project pages, an index the model can maintain further |
| **Open Brain (Nate B. Jones)** | the `webhook` sink posts each graded item as JSON; put a small adapter in front of your Open Brain capture function (none ships yet) |
| **Hindsight** | the `hindsight` sink calls `retain` with the item id as `document_id`, so re-delivery upserts |
| **Miessler's PAI** | the same pipeline shape as its feed design (ingest, rate, route; write-ahead ledger); write a delivery sink for its memory |
| **Anything else** | `jsonl` on stdout: pipe it wherever you want |

## The Unix rule

Every stage is a small module behind one interface, and a new source or sink is one file plus one line of config. Scheduling is cron, a systemd timer or a Kubernetes CronJob, not ours to rebuild. A source can live in another process: `swb-feed pull` prints a source's raw items as JSONL, `swb-feed ingest` journals them exactly as `run` would, and the line between them is a versioned contract (`swb-feed-item/v1`). Private sources stay private: they never enter the open core, they pipe in.

## Data and privacy

Third-party content stays where it is fetched to: on your machine. Items marked `personal` (the inbox by default) reach views but never a delivery or a model port unless that sink or port explicitly accepts them. Secrets are removed before the first write. Nothing phones home.

## What is not in it, on purpose

A memory engine, a database server, a web app, a scheduler, a full-page article extractor, clustering of related stories. Each is a candidate for later, if real use asks for it.
